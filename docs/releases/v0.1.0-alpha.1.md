# v0.1.0-alpha.1

## Date

2026-05-03

## Highlights

- PHP 8.2 and PHP 8.4 compatible modernization baseline.
- VectaVoIP provider registration, status, rate preview, credential rotation,
  signed webhooks, and local provisioning foundation.
- Authenticated v1 REST API foundation with OpenAPI documentation.
- Billing/rating regression services and reporting reconciliation checks.
- Asterisk/PJSIP launch baseline and payment module guardrails.
- Date-windowed migration support for customers, VoIP settings, and CDRs.
- Release readiness, portal crawl, and security hardening scaffolds.

## Upgrade Notes

- This is an alpha build for sandbox/operator validation.
- Do not expose legacy portals directly to the public internet.
- Keep security hardening and toll-fraud controls in front of any production use.

## Database Migrations

- Provider import log.
- Provider webhook event log.
- VectaVoIP installation records.
- VectaVoIP DID inventory.
- A2BillingPlus audit log.

## Provider Changes

- VectaVoIP is the first-class provider module.
- Production-compatible provider API is implemented locally under
  `/api/vectavoip`; deployment to `api.vectavoip.com` is still required.

## Payment Changes

- Stripe module foundation and webhook signature verification are present.
- Braintree configuration validation exists but remains optional.
- Legacy direct-card gateways remain unsafe/disabled.

## Security Notes

- Security controls are scaffolded, including credential policy, CSRF tokens,
  rate-limit policy, and audit logging.
- Full legacy-page hardening must be completed before public production use.

## Known Limitations

- Admin, customer, and agent portals are still legacy surfaces.
- WebRTC is deferred until SIP/PJSIP flows are stable.
- Payment checkout/session creation is not production-complete.
- VectaVoIP production deployment and live-provider validation are still needed.
